## The problem

I came across the crisesStorylinesRAG project — a research pipeline built by scientists at the European Commission's Joint Research Centre (JRC) that uses LLMs and Retrieval-Augmented Generation on news data to generate structured causal storylines for global disasters. The pipeline produces a dataset: thousands of real disaster events, each annotated with a causal knowledge graph, narrative storyline, hazard type, affected region, and timeline.

The core unit of the dataset is the **causal triplet**: a structured (subject, relation, object) statement extracted from news text describing what caused, prevented, or worsened a disaster. Something like *"deforestation → causes → increased flood severity"* or *"early warning system → prevents → casualty loss"*. The JRC pipeline extracted 24,954 of these triplets across 3,158 events, covering 176 countries and a decade of global disaster news. Each event might have half a dozen triplets; some have dozens.

The researchers had done something genuinely impressive. What they hadn't built was a way to explore it visually — to actually navigate the data, look for patterns across regions and years, read individual storylines, and trace cause-and-effect chains through a graph. The HuggingFace demo they published was a text interface. It did the job, but it didn't let you *see* the data.

I wanted to see the data.

## What I built

A full interactive dashboard deployed at [crisis-storylines-global.vercel.app](https://crisis-storylines-global.vercel.app), covering the full dataset of 3,158 disaster events with five main sections:

- **World map** — all events plotted geographically, filterable by year, region, and disaster type; click any pin to go straight to the event
- **Event explorer** — browse individual events with their full AI-generated causal storyline and an interactive force-directed knowledge graph showing how causes, impacts, and actors connect
- **Trends** — charts showing disaster frequency over time, breakdowns by hazard category, and regional patterns
- **Insights** — thematic summaries generated by Gemini 2.5 Flash, answering twelve research questions drawn from the full dataset using RAG
- **Methodology & Audit** — transparency pages explaining exactly what the data is, where it comes from, what processing I applied, and how the AI-generated content was produced

The whole thing is open access — no login, no account, just the data.

## How I built it

The data pipeline came first. The original DisasterStory.csv from the JRC open data repository needed preprocessing — normalising inconsistent country names, filtering incomplete records, structuring the knowledge graph triplets into a format React could render efficiently, and generating the static JSON files the app serves. That work lives in the `/scripts` and `/data` directories.

The knowledge graph visualisation was the most technically interesting part. Each event's triplets become nodes and edges in an interactive force-directed graph — subjects and objects as nodes, relations as labelled edges. Rendering 24,954 triplets across 3,158 events required building per-event graph structures rather than trying to visualise the whole dataset at once, then tuning the physics settings in react-force-graph-2d, handling label collision, and thinking carefully about what to show at different zoom levels. The graph makes the causal structure of a disaster immediately legible in a way that reading a list of triplets does not.

The Insights page uses Retrieval-Augmented Generation to answer twelve thematic research questions against the full triplet dataset. The reason for RAG here is straightforward: 24,954 triplets is far too much data to dump into a single model context window, and most of it would be irrelevant noise for any given question. Instead, each question is first converted into a vector embedding using a sentence-transformers model (`all-MiniLM-L6-v2`), and LanceDB runs a semantic similarity search across all triplets to retrieve the 100 most relevant ones for that specific question. Those 100 triplets — not 24,954 — are what goes into the Gemini 2.5 Flash context window, along with the question and a system prompt grounding the model in the dataset's scope and limitations. The result is a focused, evidence-backed answer rather than a generic hallucination. All twelve insights were generated once, offline, and baked into a static JSON file — so the Insights page loads instantly, with no runtime LLM calls.

I used shadcn/ui throughout for components and React Leaflet for the world map. The whole project was built in VS Code using my standard vibe coding approach with Claude.

## How long it took

Two days, start to finish. One day to design and build the core application — data processing, map, event explorer, routing. A second day to build out the Trends and Insights sections, add the knowledge graph, write the Methodology and Audit pages, and deploy to Vercel.

## Where it stands now

Live, public, and fully functional. I built this with no external brief, no client, and no deadline — just a dataset I found interesting and a few hours to see what I could do with it.

It's worth being explicit about what this project is and isn't. It's a personal visualisation tool built out of curiosity. It has no academic affiliation and no connection to the original researchers. All credit for the underlying data and methodology belongs entirely to the JRC team. If I've contributed anything, it's a more explorable interface for work that was already impressive.

The broader point this project illustrates: the same skills and tools I use to build production software for clients are equally useful when applied to a dataset I find intellectually interesting on a Tuesday afternoon. That's actually how most of the interesting side projects start.
